When Paul asks to develop, design or work out a computation (e.g. the likelylikes
scoring maths), the deliverable is the design written up as documentation. Do not
scaffold a package, add tooling or implement code unless Paul asks for it.

**Why:** 2026-10-21, asked to "develop the scoring computation", I started an
npm/tsconfig/vitest scaffold to implement it. Paul interrupted: "You are too
ambitious. I just want the scoring mathematics designed and documented, not
implemented as code."

**How to apply:** Read "develop / design / work out" as design-and-document.
Offer implementation as a one-line next step instead of starting it. Throwaway
verification scripts in the scratchpad are fine; changes to the repo beyond docs
are not.
